# Project Structure & Conventions

Task Management REST API. Use this as the blueprint for adding or modifying code so everything stays consistent.

## Stack

- **Runtime:** Node.js + Express 5, TypeScript (strict, `module: NodeNext`), ESM (`"type": "module"`)
- **Database:** PostgreSQL via Prisma 7 (`@prisma/adapter-pg`); Neon in dev, `docker compose up -d postgres` locally
- **Auth:** server-side sessions in an httpOnly cookie (`Session` table) + Passport Google OAuth
- **Email:** Brevo / Resend / Nodemailer
- **Logging:** Winston (+ Morgan piped into it)
- **Jobs:** BullMQ (Redis)

## Layering & request flow

```
server.ts → routes/*Route.ts → middlewares (protect, authorize) → controllers/*.controller.ts → prisma (config/prisma.ts) → utils/*
                                                                          ↓ on error
                                                                  catchAsync → globalErrorHandler
```

Each domain (auth, task, user) is a triple: **model + controller + route**.
**To add a new domain:** create all three files and mount the route in `server.ts` under `/api/<domain>`.

## Conventions

### Module system
- ESM only. Use `import`/`export`, and **always include the `.js` extension** in relative imports (`"../config/prisma.js"`) — even though the file is `prisma.ts`. NodeNext resolution maps it to the `.ts` source and the emitted `dist/*.js` keeps working; a `.ts` extension would break the build.
- The Prisma client is the default export of `config/prisma.ts`; import model types/enums from `../generated/prisma/client.js`.
- Controllers: named exports per handler.
- Routes: `export default router`.
- Utils: default export for a single thing; named exports when multiple.

### Controllers (reference: `src/controllers/task.controller.ts`)
- Wrap every handler in `catchAsync(async (req, res, next) => { ... })`.
- Validate inputs early; on failure return `next(new AppError(message, statusCode))`.
- Get the user with `requireUser(req)` (from `auth.middleware.ts`) — `req.user` is typed optional, and the helper turns a missing user into a 401 instead of a crash: `const userId = requireUser(req).id;`.
- Read config from `env` (`config/env.ts`), not `process.env`, for anything required.
- **Workspace isolation**: every workspace-owned row (tasks, and later projects, labels…) is reached through an ACTIVE membership check.
  - Routes with `:workspaceId` mount `requireWorkspaceMember` (→ `req.membership`) and, where needed, `requireWorkspaceRole("owner", "admin")` (rest args).
  - Item routes without a workspace id (`/api/tasks/:id`) load the row, then `requireActiveMembership(row.workspaceId, userId)`.
  - Non-members get the SAME `404` as a missing row — never a `403` that confirms it exists.
  - Per-row rules (e.g. Members edit only tasks they created) live in `utils/taskPermissions.ts`, not inline.
- Validate ids (`validator.isUUID`), enums and dates **before** Prisma runs, so bad input is a 400, not a 500.
- **Never pass `undefined` or raw body objects into a `where`**: Prisma reads `{ field: undefined }` as *no filter* (matches every row) and an object as a filter operator (`{ "not": "" }`). Guard with `typeof value === "string"` first.
- Logging: `logger.info` on success, `logger.warn` on expected failures (not found, bad input), `logger.error` for unexpected.
- Success response shape:
  ```js
  res.status(200).json({ status: "success", data: { task } });
  // lists:   { status: "success", results: tasks.length, data: { tasks } }
  // create:  201
  // delete:  204, data: null
  ```

### Routes (reference: `src/routes/taskRoute.ts`)
- `const router = express.Router()`.
- Apply `protect` (and `authorize(...)` where needed) before the controller.
- Mounted under `/api/<domain>` in `server.ts`.

### Data model (reference: `prisma/schema.prisma`)
- Change the schema, then `npm run db:migrate -- --name <what-changed>`; commit the generated migration folder.
- UUID ids (`@default(uuid(7)) @db.Uuid`), `createdAt`/`updatedAt` on every model, `@db.Timestamptz(3)` for dates. Comment non-obvious fields.
- Secrets (password, tokens) are omitted from every query by the global `omit` in `config/prisma.ts`; add new secret columns to `USER_SECRET_FIELDS`. Opt back in per query: `omit: { password: false }`.
- Field rules Prisma can't express (email format, password length, trimming) live in `utils/userValidation.ts`; hashing in `utils/password.ts`.

### Errors
- `AppError(message, statusCode)` (`src/utils/AppError.ts`) — sets `status` (`fail` for 4xx, else `error`) and `isOperational`.
- `catchAsync` forwards rejections to `next`.
- `globalErrorHandler` (`src/middlewares/error.Middleware.ts`) translates Prisma known errors (`P2002` unique → 400, `P2025` missing → 404) and hides non-operational messages. **Mounted last** in `server.ts`.

### Auth
- Sessions: `startSession(req, res, userId)` (`src/services/sessionService.ts`) creates a `Session` row and sets the `afritask_session` cookie; `revokeSession` / `revokeAllSessions(userId, keepId?)` end them. Logout revokes the current one; password reset revokes all; password change revokes all others.
- `protect` (`src/middlewares/auth.middleware.ts`) hashes the cookie, loads the live session + user, sets `req.user` and `req.sessionId`.
- Email/OAuth links: `issueAccountToken` / `consumeAccountToken` (`src/services/accountTokenService.ts`). Tokens are single-use (consume is an atomic conditional update) and stored only as SHA-256 hashes; issuing retires the previous unused one.
- Rate-limit sensitive routes with a fresh limiter per route: `router.post("/login", credentialLimiter(), login)`.
- `authorize(...roles)` (`src/middlewares/role.middleware.ts`) for RBAC, applied after `protect`.

### Cross-cutting
- Security middleware in `server.ts`: `helmet`, `cors` (env-driven origin), `express.json()`, `express.static('public')`, `morgan` piped into Winston.
- Logging: import `logger` from `utils/logger.ts`; caught errors are `unknown`, so log `describeError(error)` (stack) or `errorMessage(error)` (one line).
- Background work: BullMQ queues + workers in `jobs/` (Redis via `config/redis.ts`), registered inside the `app.listen` callback.
- DB: `connectDatabase()` (from `config/prisma.ts`) called once at the top of `server.ts`; exits on failure.
